# 装扮抽卡 · DRESS GACHA

一个独立的本地 WebUI：四档强度 × 18 个品类随机抽卡，只出提示词，或直接联动本机 ComfyUI 出图。

```
http://127.0.0.1:8770
```

**桌面快捷方式**（推荐）

桌面上有两个图标，双击即可：

| 图标 | 作用 |
|---|---|
| **装扮抽卡 · 启动** | 启动服务并自动打开浏览器；已经开着就只打开浏览器，不会起第二份 |
| **装扮抽卡 · 关闭** | 关掉服务，确认后提示「已关闭」／「没有在运行」 |

实现说明：

- `启动.ps1` / `关闭.ps1` 承载逻辑，`启动.bat` / `关闭.bat` 只是带 `-ExecutionPolicy Bypass` 的入口，所以不用改系统策略
- 启动后把 pid 写进 `data/server.pid`；关闭时**只杀这个 pid**，不会误伤其它 python 进程
- pid 文件丢失时回退为「谁占着 8770 就停谁」，并且只对 `python*` 进程下手
- 启动会等端口真正起来（最多 20 秒）再报成功，失败则指到 `data/server.log`

命令行启动：

```powershell
cd D:\deepseek\dress-gacha
py -3.13 server.py
```

零第三方依赖（标准库 + ComfyUI HTTP API）。

**界面美化（按 better-ui 规则）**

| 类别 | 改动 |
|---|---|
| **交互状态** | 按下缩放 `0.96` / `150ms ease-out`，禁用态不缩放；hover 限定在 `@media (hover: hover)`，避免触屏点完卡住 |
| **焦点可见** | 全局 `:focus-visible` 用 2px 主题色描边加 2px 偏移，不靠颜色单独传达 |
| **动效** | 所有过渡改为**具名属性**（`background-color` / `border-color` / `box-shadow`），不再用 `all` |
| **reduced-motion** | 全局降级为 `.01ms`，位移与缩放全部取消，保留静态状态 |
| **深度** | 卡片、面板改用**分层阴影**代替硬边框；保留 `1px solid transparent` 让 forced-colors 模式仍能描边 |
| **图片** | 内容图加 1px 纯黑/纯白内描边（`oklch(0 0 0 / .1)` / `oklch(1 0 0 / .1)`），不用调色板中性色以免边缘染色 |
| **嵌套圆角** | 外圆角 = 内圆角 + padding，卡片内层用 `calc()` 跟随 |
| **分组** | 十二个设置格各自带 1px 内描边与极浅底色，不再靠手感区分 |
| **排版** | 标签 9.5–10px 并收紧字距；组内 3–6px、组间 10–14px，节奏替代均分间距 |
| **滚动提示** | 树的高度按**整行**量化（25px/行），底部渐隐并只在真的溢出时出现 |
| **滚动** | 所有内滚容器加 `overscroll-behavior: contain`，滚到底不会带走整页 |

同时修掉了美化过程中引入的一处布局回归：`.grow` 格子曾把 fr 预算吃满、膨胀到 **529px**，导致面板溢出 331px；改成高度封顶后两个格子回到 184px，**溢出归零**。

**界面布局**：整页**不滚动**，一屏看全。

| 区域 | 内容 |
|---|---|
| **顶部** | 标题 · 模式切换 · ComfyUI 状态 |
| **左侧设置区** | 词库模式 2 栏 / API 模式 3 栏网格，所有控件一屏排开；主操作按钮固定在底部 |
| **右侧结果区** | 顶部工具条（API 文本 / 复制全部 / 清空），下方卡片网格自行滚动 |

实测在 1280×800、1440×900、1920×1080 三档分辨率下：**页面滚动量 = 0**，设置区溢出 = 0，主按钮始终可见。

只有两处在极端情况才会滚动：结果卡片多了在结果区内部滚动；屏幕高度不足 800px 时设置区内部滚动（不会推动整页）。

## 一、新增：提示词改写构图

已经抽出来的提示词，卡片上有「**改写构图**」按钮：

1. 点开，选目标构图（大头照 / 半身照 / 全身照 / 正反全身照 / 横向三栏）
2. 点「预览改写」，会显示删掉了哪几处
3. 点「应用」，卡片里的提示词就地更新，并标注新构图

**改写做什么**：原提示词里带着只属于它自己构图的句子——正反全身照会写 `back view`、`left/right half`、`two panels`、`each panel occupying half the frame`。改成单人构图时这些必须删掉，否则模型照旧画两个人。

实测：

| 从 | 改为 | 删除 |
|---|---|---|
| 正反全身 | 全身照 | 8 处（back view、left half、right half、each panel…） |
| 正反全身 | 大头照 | 9 处（上面 + full body、whole figure） |
| 正反全身 | 正反全身 | 0 处（保留） |

## 二、新增：中断

设计或出图卡住时，进度条旁边有「**中断**」按钮：

- **立即解锁界面**：先无条件复位按钮、清掉 busy 标志、把转圈改成「已中断」，再去通知后端
- **真的停掉 ComfyUI**：同时调 `/interrupt` 和 `/queue {clear:true}`
- **作废在途的设计请求**：用一个世代计数器，中断后迟到的响应不会覆盖界面
- 实测响应 **0.0 秒**（ComfyUI 空闲时 `/interrupt` 会阻塞，已放到后台线程并加 5 秒上限）

## 三、修复：切档位后品类文本消失

**原因**：`styles` 为空列表时被当成「多选空集」，走的是随机挑一个品类的分支，所以块还在但内容换了；切换档位时如果正好处于这个状态，看上去就像品类块没了。

**修法**：`compose_user` 改成固定骨架，无论哪一档、有没有选品类，这七块都在：

```
【必须逐项设计的维度】
【品类锚点 / 品类范围 / 限定品类】   ← 永远存在
【该品类的设计方向】
【可选的具体款式】
【构图】
【用户需求】
```

> 「【语言】」那一块后来被移走了：输出语言现在是 system 通道的固定规则，排在最前面（见「输出语言：固定中文」）。

不选品类时锚点显示「不限（全部分类开放）」，而不是偷偷塞一个随机品类。

实测四档 user 长度完全一致：选品类 936 字，不选 831 字。

## 四、新增：底模可选

出图参数里加了「底模」下拉，读 ComfyUI 的 12 个 diffusion model，按家族分组：

- **MOSS 底模（推荐）**：`moss_image_sft`（默认）、`Moody-Moss-Mix-V4.1`、`PornMaster_Moss_MIX_V2`
- **其它（架构不同，可能出错）**：idol、minimax_h3、qwen、krea、seedvr2 等

选中的底模会写进 Moss 工作流的 UNETLoader 节点。实测指定 `moss_image_sft` 出图正常（61 秒，816×1232，正反双视图）。

## 五、布局：一屏看全，不用滚动

改造前的窄侧栏控件挤成一列，必须上下滑。现在：

- **整页 `overflow:hidden`**，body 高度锁定 100vh
- **左侧设置区**用 CSS Grid 分栏：词库模式 2 栏、API 模式 3 栏，把纵向高度压成横向宽度
- **主操作按钮 sticky 固定在底部**，任何时候都点得到
- **右侧结果区**独立滚动，不影响左边
- 「发给 API 的文本」默认收起，点工具条「API 文本」才展开，不占常驻高度

| 分辨率 | 页面滚动 | 设置区溢出 | 主按钮可见 |
|---|---|---|---|
| 1280×800 | 0 | 0 | ✅ |
| 1440×900 | 0 | 0 | ✅ |
| 1920×1080 | 0 | 0 | ✅ |

**左栏填满**：品类树和 LoRA 区标记为可伸展格子（`.cell.grow`），会吸收剩余高度而不是留白。

| 区域 | 实测高度 |
|---|---|
| 设置区内容 | 848px |
| 面板总高 | 874px（**占 97%**） |
| API 模式品类树 | 471px（18 大类全部可见） |

### 5. 提示词骨架公式

```
质量词 → 主体（年龄/种族）→ 体型 → 发型发饰 → 妆容
      → 服装结构（领型 · 胸 · 腰 · 裙 · 开叉 · 背面）
      → 鞋 → 姿态 → 表情 → 光 → 背景 → 镜头 → 视角 → 质感
```

四条让这类图不出错的硬规则（也是本工具词库的写法）：

1. **服装写结构，不写形容词**。「高光缎面 + 交叉提拉皱褶 + 腰侧放射抓褶 + 开叉到大腿上部 + 背后交叉包裹」比「华丽的礼服」有效一个量级。
2. **光写器材与方向**。「大柔光箱正面主光 + 补光 + 地面反光」比「柔和的光」可控。
3. **背景写无缝与色值**，不写「灰色背景」——否则模型会给你加墙、加窗、加杂物。
4. **双视图只改视角词**。主体描述一个字不动，否则正背面会变成两个人。

## 二、WebUI 怎么用

两种模式，顶部按钮切换：

### 模式一 · 提示词库抽卡（本地组合，毫秒级）

**四档强度**

| 档位 | 含义 | 底模 |
|---|---|---|
| 正常版 | 完整着装，可露肩露背，无性暗示 | Krea2 ProsumerShots |
| 擦边版 | 高暴露剪裁、薄透贴身、走光边缘，不露点 | Krea2 ProsumerShots |
| 裸露版 | 露点、半遮半掩、全裸 | Krea2 Uncensored V8 |
| 色情版 | 裸露之上叠加性道具与性元素（乳钉、项圈、束缚、玩具） | Krea2 Uncensored V8 |

档位切换会自动换底模、换负面词（正常/擦边档屏蔽 nsfw，裸露/色情档屏蔽马赛克与审查词）。

**十六个风格族**

缎面礼服 · 婚纱 · 旗袍 · 古风仙侠 · 职场OL · 护士 · 空姐 · 教师 · 泳装 · 情趣内衣 · 洛丽塔 · 睡衣居家 · 皮衣机车 · 运动装 · 和服浴衣 · 舞台偶像

每个风格族自带场景库、体型库、配色库；服装随档位变化（同一件衣服「穿着 → 剪开 → 脱下 → 加道具」四段式），所以同一风格在四档下是连续的，不是四套不相干的东西。

**两种动作**

- **抽提示词**：纯组合，毫秒级，一次最多 50 条，每条给英文 prompt + 负面词 + 中文叙事，可单条复制或一键全复制。
- **抽并出图**：抽完直接串行提交 ComfyUI（Krea2，8GB 显存一次一张），逐张回填进度和图片，失败的卡片可单张重出。

seed 可留空（随机）或指定（可复现）；`数量 × 风格 × 档位` 的组合总数为 **3,067,084,800**。

### 模式二 · API 设计（LLM 现场设计，四档设计方法）

一句话需求 → 模型按所选档位的**设计方法**逐维度设计 → 输出可直接出图的中文提示词。

**四档设计方法**（`design_methods/` 下四份独立文本）

| 档位 | 文件 | 设计重点 |
|---|---|---|
| 正常版 | `01_正常版.md` | 完整着装、体面耐看；八维逐项给具体值 |
| 擦边版 | `02_擦边版.md` | **暴露的几何关系**（领口线压在哪、露出多少比例、开衩起点与终止高度）+ 结构支撑（马尾衬/鱼骨/腰封） |
| 裸露版 | `03_裸露版.md` | 裸露部位逐项清点（露/遮/半遮）+ 遮挡物 + 皮肤受光 |
| 色情版 | `04_色情版.md` | 裸露结构 + **道具逐件设计**（材质/佩戴位置/连接关系/勒痕形态） |

每档都要求模型输出 `{"rewritten_prompt", "design_notes", "wh_ratio"}`，并在框内固定背景（`#E8E8E8` 无缝棚拍）。

**在界面里直接改**：档位卡下方「查看 / 编辑当前档位」打开编辑器

- 四个档位各一个 tab，点一下切换
- 文本框里就是原始 Markdown，改完点「保存」
- 保存时自动把上一版写到 `.bak`，改坏了可以手动还原
- **保存即生效**：后端每次生成都重读文件，不用重启服务
- 左下角实时显示「未保存 · N 字（原 M 字）」，有未保存改动时变黄
- 也可以直接编辑 `design_methods/*.md` 文件，效果一样

**设计维度**取自 `character-appearance-design` 技能（`engine/design.py`）：

```
1 轮廓与体型  2 面部结构  3 五官  4 毛发与皮肤
5 化妆        6 服饰结构  7 饰品  8 鞋
```

**品类 = 多选（指定随机的范围）**

分类树照你给的两份 gemini 文件建成：**18 大类 / 75 小类**，两级都可选。

- 点**大类**名 → 单独选中（该大类内所有小类进随机池）
- 点**▸** → 展开小类，点**小类** → 精确到子类
- **API 模式支持多选**：点几个就选中几个，这些一起构成「随机范围」——模型被告知「只允许从以下品类中选一套，不要跨品类混搭」
- 再点一次取消；点「清空（全随机）」恢复全域随机

品类树来源（`engine/taxonomy.py`）：常规上装、外套与大衣、下装裤装、下装半裙、连体与套装、内衣家居贴身、晚礼服与婚庆、风格与美学流派、三坑与亚文化、职业装与行业制服、古装与民族服饰（内含历代 9 段）、运动与户外、特殊人群、东方幻想仙侠、西方奇幻史诗、科幻赛博、二次元游戏舞台、情趣制服角色扮演。

**词库模式只显示它覆盖的 10 大类 / 15 小类**。词库有 16 个手写服装池，映射到分类树的部分节点；未覆盖的节点不列出，因为列出来也只能静默回退成随机，等于忽略你的选择。

**进度、预览、**第二轮审计：出图与保存的真 bug**

### 1. 「出这张」点了没反应（严重）

两层原因叠在一起：

| 层 | 问题 |
|---|---|
| 前端 | `renderSingle` 直接 `el.querySelector('.card-img').innerHTML = ...`。**没出过图的卡片根本没有 `.card-img` 元素**，这里空指针抛错，被 `catch` 吞掉，页面上只剩一个转瞬即逝的 toast |
| 前端 | 即使元素存在，它调的 `/api/rerender` **不读卡片上的提示词**，后端会重新 `composer.draw_one()` 自己再拼一份，所以「大头版」和「构图版」点出来是同一份东西 —— 这就是你说的两个版本 bug 不一样 |

修法：
- 元素不存在就先创建，不再假设它存在
- 改成提交 `/api/render_async` + 轮询 `/api/render_status`，并且**把卡片当前显示的提示词原文发过去**，切到大头版就画大头版

### 2. 长任务请求永不返回（严重）

`/api/render_moss` 是同步阻塞的，一次冷启动要 7–8 分钟。浏览器把请求挂那么久，任何网络抖动都会让前端一直停在「出图中…」。

更糟的是 `api()` 失败后会**重试一次** —— 对 8 分钟的出图来说，等于再跑一遍。

修法：
- 新增 `/api/render_async`（提交即返回 job id）与 `/api/render_status`（轮询取图）
- `api()` 按超时长度区分：**≥120 秒的请求不重试**

实测：提交 **0.0 秒**返回 job id，**32 秒**后轮询拿到图，34 步。

### 3. 刷新后画风选择被清空（真 bug）

```js
applySavedState();     // L275  恢复 state.vstyles
...
state.vstyles = [];    // L319  异步加载时无条件清空 ← 把恢复的直接抹掉
```

保存在写、读也在读，但异步初始化把它覆盖了，表现就是「实时保存没用」。改成只在没有恢复值时给默认空数组。

### 4. 重构时误删的三个路由

把渲染主体抽成 `render_moss_blocking()` 以便异步复用，过程中误删了 `/api/api_request`、`/api/rewrite_composition`、`/api/cancel`。已全部补回并逐个验证。

**代码审计：修掉 3 个真实 bug**

### 1. 出图无响应 —— `CANCEL_FLAG` 永不复位（严重）

`/api/render_moss` 里检查了中断标记，但**从不清除**：

```python
if CANCEL_FLAG.is_set():
    self._json({"error": "已中断"}, 499)
    return
```

只要点过一次「中断」，这个标记就永久为真，之后**每一次出图都立刻返回 499**，表现就是「点了没反应」。清理逻辑只写在批量渲染那条路径上，单张出图完全没有。

修法：新请求进来时清掉旧标记 —— 中断只属于它当时打断的那一次。

实测：修复前 `{"error": "已中断"}` → 修复后 **40 秒出图成功，34 步**。

### 2. 锁范围过大 —— 单次出图会卡住其它所有出图接口（严重）

```python
with RENDER_LOCK:
    ...
    comfy.wait(pid, timeout=900)   # 持锁最长 15 分钟
```

`RENDER_LOCK` 本意是「一次只跑一张图（8 GB 显存）」，但临界区里包住了 `comfy.wait()`，于是一张图在跑的时候，`/api/draw`、`/api/rerender`、`/api/render` 全部阻塞到 HTTP 超时。

修法：锁只包住 `submit()`（真正占 GPU 的那一瞬），等待放到锁外面。

实测：修复前 `/api/rerender` `TimeoutError` → 修复后正常返回。

### 3. 两条渲染路径的图片不能放大

`抽并出图`（pollJob）和 `API 出图` 这两处插入 `<img>` 后没有调用 `wireImages()`，图片只有 `zoomable` 类、没有点击处理器，点不开。

修法：所有 5 条插入图片的路径统一走 `wireImages()`。

**实时保存改为双轨**

之前每次击键都同步序列化整个状态并写 localStorage，长需求文本打字会发黏。现在分两条路：

| 写入路径 | 触发 | 时机 |
|---|---|---|
| `saveState()` | 离散选择（档位、品类、画风、人物风格、动作、详细度、模型、比例等） | **立即写**，丢一个就等于丢一个决定 |
| `queueSave()` | 文本输入（需求文本） | **防抖 250ms**，停手才写 |
| `flushState()` | 关闭页面 / 切到后台 | 强制写，把未提交的防抖内容也刷出去 |

实测：

| 场景 | 结果 |
|---|---|
| 连续输入 20 个字符 | 过程中 **0 次**写盘，停手后 **1 次** |
| 改下拉框 | **立即** 1 次 |
| 输入后立刻 flush | 文字被强制写入 |

**背景与地面归构图模块管**

背景（纯色 `#E8E8E8` 中性浅灰白）与地面（`#D8D8D8`）曾经写在正常版档位方法里，标着「固定，不可换」。那会造成一个硬冲突：档位写死「构图：全身入画，主体居中」，而用户实际选的可能是大头照或正反全身照 —— 模型同时收到两套互斥的画幅指令。

现在背景与地面由「构图与姿态」模块统一输出，档位不再碰：

- 背景对所有构图一致
- 地面只出现在**画面里有地面**的构图：全身照 / 正反全身照 / 横向大头+正反全身照
- 大头照（切在锁骨以上）与半身照（切在大腿中部）没有地面

**四档方法：只写调性，维度清单不再重抄**

四个档位方法文件（`design_methods/0*.md`）原来各自带一份维度清单（正常版列了「轮廓与体型 → 面部结构 → 五官 → … → 鞋」八项），和系统提示词的「设计维度与顺序」模块**是同一份清单写了两遍**，篇幅大且容易改一处漏一处。

现在四档方法只做两件事：

1. **声明本档的侧重**，不再重抄维度清单，改成一句引用：

   ```
   按系统提示词「设计顺序」的第一至第七步逐项给出具体值
   第一步 体型 → 第二步 面部骨相 → 第三步 五官 → 第四步 皮肤与毛发 → 第五步 妆容 → 第六步 服装 → 第七步 饰品与鞋
   ```

2. **只写本档独有的东西** —— 调性、光线、该档专属的造型要求（例如擦边版的「剪裁与露肤的几何关系」、裸露版的「三处的具体做法」、色情版的「道具系统」）。

维度清单的唯一权威在 `engine/design.py` 的 `DIMENSIONS_TEXT`。改它四档同时生效。

另外，档位里的「禁止出现比例数字、像素、分辨率」也顺手改了措辞：

```
禁止出现画面规格（画面比例如 2:3、像素、分辨率）
```

原措辞会被读成「禁止写几头身」，与维度模块要求的「比例用几头身」打架；现在明确只禁**画面规格**，人物比例照写不误。

**大头提示词模块与自动分离**

「大头提示词」是一个**系统提示词模块**，紧跟在「构图与姿态」之后。它要求模型把大头照提示词写成整条提示词末尾的一个 `-XXX-` 片段，于是**一次 API 调用同时得到两版**：

| 版本 | 内容 |
|---|---|
| 构图版 | 剥掉 `-XXX-` 之后的剩余部分（完整可用的构图提示词） |
| 大头版 | `-XXX-` 片段本身（保留前后短横线） |

分离在后端 `split_headshot()` 完成，自动生效，不需要再点一次按钮、也不额外消耗一次模型调用。卡片上出现「构图版 / 大头版」切换，两版各自独立出图。

拆分规则按**边界**判定而不是按「第一个 `-XXX-`」判定：提示词里本来就有 `85mm-lens`、`close-up`、`e-commerce` 这类带连字符的词，只有**独立成词**的短横线才是片段边界。

判定分两级：

| 级别 | 条件 | 说明 |
|---|---|---|
| 第一级 | 片段在整条提示词**末尾** | 结尾短横线后面只能是分隔符或结束，所以 `...headshot-` 是边界，而 `...e-commerce` 是词内连字符，不会混淆 |
| 第二级 | 片段在**中间** | 模型没把片段放末尾时启用。候选按**长度从长到短**排序取最长，且片段必须**描述五官**（脸/眼/眉/发/妆/耳/颈/锁骨等）——这一条把散文里的 ` - soft lighting - ` 排除掉 |

误判会把构图版整条吞掉，所以这两条规则必须写死。

卡片上的「生成大头版提示词」按钮保留为**手动兜底**：模型没按契约输出 `-XXX-` 时才用得上，它会再调一次模型把近景部分抽出来。

**发色与纹身（并入设计维度）**

放在**第 4 步「皮肤」**之后，因为纹身本身就长在皮肤上，发色也属于体表特征——不另开大类：

### 冲突一：大头照却在描述身体

大头照规定「画面切在锁骨、肩部以下不入画」，但静态姿态段要求「双腿分开约与肩同宽、双臂自然下垂、重心均匀落在双脚」——**这些部位根本不在画面里**。动作版又追加一条「让角色处于正在发生的动作中」，而静态那句「正对镜头、无表情」还留在前面，模型会二选一。

| 改法 | 结果 |
|---|---|
| 给大头照单独写姿态 | 只讲头部、颈部、锁骨三处的相对关系，不提任何身体部位 |
| 给大头照单独写动作 | 改为小幅头部与颈部动作（侧头、收下巴、颈侧拉伸），写头部转向角度与颈线方向 |
| 动作**真正替换**静态姿态 | `compose_composition` 先剥掉静态句再接动作句，不再两者并存 |

### 冲突二：详细度与裸露档互相打架

详细度「繁华」要求 **4–6 件分层叠穿、三层以上材质**；裸露档要求 **全裸 / 只剩饰品 / 丁字**。两条同时生效时，模型收到「穿 6 件」和「不穿」。

| 改法 | 结果 |
|---|---|
| 新增 `DETAIL_BODY_ONLY` | 裸露档与色情档下的三档详细度改为控制**饰品与身体装饰的密度** |
| `resolve_for_tier()` | 按档位自动选服装版或裸露版文本 |
| 明确禁止词 | 裸露版的繁华档明文写「严禁出现『叠穿』『多层』『外披』『腰封』这类服装层数的词」 |

裸露档下的三档现在是：

| 档位 | 饰品密度 |
|---|---|
| 简约 | 全身 0–1 件，单件成立 |
| 普通 | 2–4 件成组 + 允许一件极少布料 |
| 繁华 | **5 件以上成组**（头/耳/颈/胸/手/腰/腿/臂/脚链）+ 允许身体彩绘、贴片、绑带、锁链 |

| | 之前的做法（错的） | 现在的做法 |
|---|---|---|
| 判定 | 写在发给 API 的文本里，让模型自己决定 | **纯程序判定**：`needs_headshot(composition)`，只有大头照构图不需要 |
| 执行 | 同一次调用里多要一个字段 | **独立的第二次请求**，把已定稿的设计作为参考喂回去 |
| 可见性 | 请求文本里混着字段说明，读起来乱 | 请求文本只讲这一次的构图，干净 |

**为什么必须走原生 `/api/chat`，不能用 `/v1/chat/completions`**

Ollama 的 OpenAI 兼容端点**忽略 `options.num_ctx`**。它默认只给 4096 token 上下文，而本工具的系统提示词本身就有 5384 字（≈4140 token），所以请求在模型看到之前就被拒了：

```text
HTTP 400: request (4140 tokens) exceeds the available context size (4096 tokens), try increasing it
```

原生 `/api/chat` 认 `options.num_ctx`，所以本地通道走它，请求体带三样东西：

| 字段 | 值 | 作用 |
|---|---|---|
| `options.num_ctx` | `32768`（`OLLAMA_NUM_CTX` 可改） | 把上下文窗口从默认 4096 撑开，装得下 4140 token 的提示词 |
| `think` | `false` | qwen3 系列会先思考再回答，`reasoning_effort: "low"` 它不认，得直接把思考关掉。不关的话 token 全烧在推理上，正文是空的，`finish_reason=length` |
| `options.num_predict` | `max_tokens` | 输出预算 |
| 本地超时 | `900` 秒（`OLLAMA_TIMEOUT` 可改） | 云端通道给 180 秒，本地不够：第一次调用要把 GGUF 从磁盘读进内存，答案又是一个 token 一个 token 生成的 |

响应格式也不同：原生返回 `message.content`（思考内容在 `message.thinking`），没有 `choices[]`。所以 `_ollama_chat()` 把原生响应**翻译回 OpenAI 形状**再交给下游，解析、分离、长度校验的代码一行都不用改。

**本地模型输出畸形 JSON 的兜底**

4B 模型经常把契约 JSON 写成「缺开头 `[` 的对象数组」：

```text
{"rewritten_prompt": "...", "design_notes": "..."}, {"wh_ratio": "2:3"}]
```

`json.loads` 直接读不了。`_extract_json()` 加了修复：先按原路径解析，失败后调 `_repair_json_list()` 把顶层对象逐个切出来合并成一个扁平 dict——切分时正确处理字符串字面量里的花括号，不会被字符串内容骗到。

实测 `qwen35-4b:latest` 端到端跑通：16–50 秒产出 2101 字构图版，`wh_ratio=2:3` 正常解析。

**已知限制**：不遵守 `-XXX-` 契约的模型，一条提示词里不会带大头片段，所以自动分离拿不到大头版。实测已知这类模型有：本地 `qwen35-4b:latest`、本地 `qwen38-9b:latest`、云端 `raccoon/sn-deepseek-v4-1-flash-1017`（后者整条输出里连一个 `-` 字符都没有）。卡片上的「生成大头版提示词」按钮走的是二次调用，**实测正常**（11.5 秒产出 638 字），用它来兜底。

> 判断方法：拿到提示词后搜一下有没有 `-片段-`。没有就不是 splitter 的锅，是模型没吐。`headshot_ready` 字段会告诉你「本次没分离出来，需要手动兜底」。

## 四、注意

- 8GB 显存 + 低系统内存时，**第一次出图是冷启动**：Krea2 约 3–8 分钟，MOSS（qwen3.5-9b + MOSS int8）约 7–8 分钟；之后同档位连续出图会快很多。
- Krea2 正常/擦边档与裸露/色情档使用不同底模，**跨档切换会触发一次模型重载**；MOSS 与 Krea2 之间切换同样会重载。
- **LLM 免费通道会限流**：25 个模型里通常 12–13 个可用。带 `:free` 后缀的（nemotron / particle / beam / openrouter 等）多数可用；`-free` 后缀的（deepseek-v4.1-flash-free 等）额度耗尽后返回 429。写提示词时会自动跳过 429 与输出过短的模型。
- **设计方法可以直接改**：`design_methods/*.md` 就是发给模型的 system 消息，改完刷新页面即生效，不用重启服务。
- 色情版输出最长（含道具逐件设计），单次约 1–2 分钟；正常版最快约 25 秒。
- ComfyUI 里如果有别人正在跑的任务，本工具会排队等待，不会抢占。

**「API 文本」按钮改为开/关切换**

原来它只会打开：

```js
block.hidden = false;      // 永远只会展开
state.reqOpen = true;
```

面板已经打开时再点，等于把 `hidden` 又设成 `false` —— 视觉上毫无变化，看起来像按钮坏了。

现在按当前状态取反：

```js
if (!block.hidden) { block.hidden = true;  state.reqOpen = false; saveState(); return; }
block.hidden = false; state.reqOpen = true;  saveState(); wireReqResize(); await refreshRequestPreview(false);
```

实测三连点：`hidden` 依次 `False → True → False`，`state.reqOpen` 同步，刷新后保持。

**大头版不再复刻构图版**

之前的本地重组在正反构图上失效：`_FRAME_MARKERS` 里没有多栏布局的词（`two panels` / `back view` / `left half` 等），找不到切分点就把**整段原样保留**，只在外面套了大头取景头尾 —— 于是大头版 = 构图版 + 两句包装。

修法两步：

1. **扩大标记表** —— 补上 `two/three panels`、`side by side`、`left/right half`、`front view`、`back view`、`diptych`、`85mm lens`、`studio backdrop` 等
2. **无论是否找到切分点，都再过滤一遍多栏残留** —— 按句切分，含多栏词的句子只保留不含该词的从句
3. 取景头里显式写 **`single panel, one person only`**，堵住模型"画两个人"的倾向

实测（正反构图提示词 → 大头版）：

| 检查 | 结果 |
|---|---|
| 与构图版完全相同 | **否** |
| 含 `two panels` / `back view` / `left half` | **全部剔除** |
| 明确单栏单人 | ✅ |
| 黑发 / 腿环 / 马甲 / 眼线 | 逐字保留 |
| 端到端（写词 4680 字 → 大头版） | **610 字，多栏残留 0** |

**正反双视角：左右分开描述 + 镜像对应**

原来的构图定义只说「正面一栏写正面所见」，模型会把同一份描述套到两栏上，导致左右错位——正面右腿的腿环，背面还是画在右腿。

现在两处构图都加了三条硬规则：

| 规则 | 内容 |
|---|---|
| **分开描述** | 左栏只写正面看得见的一切，右栏只写背面看得见的一切，不重复 |
| **镜像互换** | 背面是同一身体绕纵轴转 180°，左右必然互换：正面**右腿**的腿环 → 背面**左腿**；正面**左肩**的单肩带 → 背面**右肩** |
| **背面专属内容** | 后背衣料结构（开口/系带/拉链/镂空位置）、后腰与臀部线条、发丝背后走向、鞋跟后方样子 |

适用构件清单：腿环、袜带、吊袜带、绑带、臂环、单肩、单侧镂空、单侧开衩、发辫垂侧、单侧耳饰、单侧纹身。

两处的数量、材质、高低位置必须互为镜像，不能凭空增减。构图定义从 ~200 字扩到 **628 字**（正反）和 **605 字**（三栏版）。

**大头版只保留头部可见内容**

之前的重组只换取景头，把构图版的全身描述整段搬进大头照——左右半边、镜像、腿、鞋、裙摆、腰臀、姿势、材质全带着，大头照画不出这些东西却仍被当作指令。

| 妆容、粉底、遮瑕、修容、高光、眼影、眼线、腮红、唇釉、隐形眼镜 | 吊袜带、腰链、臂环、腕饰、脊链 |

**正反构图改用定稿文案**

`front_back` 构图定义替换为固定文本（102 字），不再拼接静态站姿与镜像规则：

**正反构图：锁死人数与姿势**

正反图偶尔冒出多个人、或某一半换姿势，根因是「同一个人画两遍」这件事没写死，模型当成两个独立人物、各自摆姿势。

两种正反构图各追加一段最高优先级规则：

| 锁定项 | 写法 |
|---|---|

| 背面 | 保持与正面完全相同的站姿，只是从背后看；不许换姿势、转身中途、坐、走、侧身 |

负面提示词同步扩充：

```
extra limbs, extra arms, extra legs, duplicated limbs,
different poses, mismatched pose, twisted body, mid-turn pose,
sitting, walking, side view, profile pose
```

正面用陈述句锁人数（避免否定词强化），负面用短语排除多余的人和姿势，两头夹击。

**卡片按钮消失（布局塌陷）已修**

现象：结果卡片只剩下标题条，底部的「复制提示词 / 改写构图 / 出这张 / 出大头版」全部看不见。

根因在网格行高：

```
gridTemplateRows: "29.6875px 29.6875px"    ← 行被压到 29px
card height:      29.6875px
overflow:         hidden                   ← 卡片把这 29px 以外的内容全裁了
```

`.grid` 是 flex 子项（`flex: 1 1 0%`）且 `overflow: auto`，隐式行高按那个 **0% 的 flex basis** 解析，于是每行塌缩到 29px；`.card` 又带 `overflow: hidden`，卡片正文连带按钮全被裁掉。

修法：

```css
.grid{ grid-auto-rows: max-content; align-items: start; }
.card{ height: auto; min-height: 0; }
.card-body{ flex: 0 0 auto; }        /* 按钮所在容器不允许被压缩 */
.card .prompt{ max-height: 190px; overflow-y: auto; }
```

| 项 | 改前 | 改后 |
|---|---|---|
| 网格行高 | 29.7 px | **630.7 px** |
| 卡片高度 | 30 px | **631 px** |
| 按钮可见 | ❌ 被裁掉 | ✅ 四个都在 |

**思考强度：默认 low，不支持则关闭**

每次请求都带 `reasoning_effort: "low"`。之前完全没发这个字段，模型就按自己的默认档位思考，慢且容易把预算花在规划上。

```python
关闭（普通）     → {"reasoning_effort": "none"}
关闭（Claude 系）→ {"reasoning": {"enabled": false}}
```

| `reasoning_effort: none` | `'OK'` ← 直接回答 |

**CFG 改为 3（原来被误锁在 1）**

节点 `39:104` 是个 If/Else 开关，标题写着「CFG 3 for 50 steps, else 1」：

旧代码把它当成 SeedVR2 放大的开关去驱动，于是永远 `false`，**CFG 一直是 1**。而这个工作流里根本没有 SeedVR2 放大节点——那个「放大：关闭」下拉框一直是空操作。

**大头版不再重新设计角色（发型漂移已修）**

原来的做法是**再发一次请求**，让模型写一份完整的大头照提示词，只在末尾附一句「骨相五官发型必须一致」。实测结果是发型、发色、刘海全变——模型把它当成一道新题，那句「必须一致」压不住它的重新创作。

3. 前面套上大头照的取景头，后面接姿态尾

```
close-up headshot portrait, framing from the collarbone up: …;
【构图版的角色描述，一字未改】;
expressionless, facing the camera straight on, …
```

| 生成方式 | 调模型重写 | **本地字符串重组** |
| 耗时 | 116 秒 | **0.00 秒** |
| 发型/刘海/碎发 | 会变 | **逐字保留** |
| 唇色/眼线/肤色/服装 | 会变 | **逐字保留** |
| 角色描述词保留率 | — | **69/69** |

找不到取景段时仍保留模型兜底（并要求逐字沿用），但正常路径不再碰模型。

**树的两级选中状态**

三个树（服装 / 画风 / 人物风格）原来只有一种「亮」的表现，导致「我选了这个大类」和「我选了它下面的小类」看起来一模一样。现在分成两级：

| 状态 | 类名 | 视觉 |
|---|---|---|
| **大类被直接选中** | `.sel` | 底色填充 + 强描边（78% 主题色）+ 外发光投影 + 白字加粗 |
| **仅小类被选中** | `.has-sub` | 极淡底色（5%）+ 单薄细线（26% 主题色），**无发光、不加粗** |
| 小类本身被选中 | `.chip.sel` | 小类胶囊填充 + 主色描边 |

```js
const _self = isSel(cat.key);                      // 大类自己点了
const _sub  = !_self && anySubSelected(cat, isSel); // 只是子类被选
row.className = 'tnode cat' +
  (_self ? ' sel' : '') + (_sub ? ' has-sub' : '');
```

两者同时成立时优先显示 `.sel`（大类确实被选中），不会被 `.has-sub` 削弱。

**LoRA 触发词：手填的加在末尾**

侧车触发词是**自动**加在最前的（模型权重对开头最敏感），但有时你还需要几个**手写**的触发词——比如 LoRA 自带的词不够准，或者要补一个画风词。为此在 LoRA 区加了一个输入框（搜索框下方、LoRA 列表上方）：

## 七、提示词模块冲突治理（方案 1 / 2 / 3）

四个常驻模块（设计档位、设计维度与顺序、服装详细度、构图与姿态）加外部模板之间做过一次全量冲突审计，按三个方案治理完毕。

### 方案 2 · 档位瘦身

四档设计方法文件不再重抄维度清单，也不再写死背景、地面、全身构图：

- 维度清单唯一权威在 `engine/design.py :: DIMENSIONS_TEXT`（第六、七步管服装结构与穿法层次）。
- 背景与地面统一由「构图与姿态」模块注入；只有画面里确实有地面的构图才写地面。
- 档位只保留「调性 + 本档专属要求（如光线语言）」。
- 比例禁令消歧为「禁止出现画面规格」，不再误伤构图描述。

### 方案 3 · 详细度瘦身

`engine/detail.py` 只拥有**密度**：单品数量、饰品件数、五金、工艺种数、篇幅占比。

- 领型、袖型、肩线、门襟、衣长、腰带、裙型、开衩、褶裥等结构字段全部归还「设计维度与顺序」，模块内以去重声明点名归属。
- 裸露档不再写「不要写多层服装」（与裸露版「先按擦边版把整套衣服设计完整」直接冲突），改为只调节**覆盖的密度**（手法组合、覆盖层数、饰品量）。
- 新增色情档专属 `DETAIL_EXPLICIT`：道具件数（性道具 / 束缚类）按三档密度分流。

### 方案 1 · 外部模板降级（注入侧清洗）

外部模板（ComfyUI enhancer 的 `prompt_files/*.txt`）为另一条管线而写：英文输出、自带 JSON 契约（`ratio_follow`）、自带比例白名单、把 brief 当上限。这些契约与本项目的规则全部相反。模板文件不能改（会改变 ComfyUI 节点自身行为），所以在注入侧新增 `engine/template_guard.py` 清洗：

| 粒度 | 做法 | 例子 |
|---|---|---|
| section | 整节删除 / 重写标题 | 「Output Size Determination」「FINAL RESPONSE CONTRACT」「露骨度五档」 |
| block | 整段删除 | 「FIRST — there are TWO separate language decisions」 |
| line | 单句删除 | 「本文其余全部条款与本段冲突时以本段为准」 |
| phrase | 句内短语改写 | 「优先使用英文直白词」→「用中文写出具体的器官与动作词」 |

清洗后的模板尾部固定追加**覆盖声明**：输出语言中文、输出格式固定 `rewritten_prompt / design_notes / wh_ratio`、比例由档位决定、维度逐项给全——后出现的规则压过模板残留。

接入点：`api_writer.compose_system()` 与 `build_prompt()` 的 `extra_template` 模块都改为 `_TG.compose_template_block()`。

**专项测试**（`.edge-dsh/_t_tpl_guard.py`）：六个外部模板 × 六类契约探针，清洗后**残留类别数 0**。

### Ollama 显存管理：写完即卸 + 手动卸载按钮

8G 显存常年被 ComfyUI 占着大半，一个留在显存里的闲置 Ollama 模型就是事故源。**已取消保温策略**，两条管理路径：

| 路径 | 行为 |
|---|---|
| **自动** | 每次 Ollama 请求体带 `keep_alive: 0`，生成完立即卸载；服务端写词返回后再后台兜底卸一次。纯写词、批量写词、写并出图一律即卸，不会有两个模型同时驻留显存 |
| **手动** | 模型选择区「卸载本地模型」按钮（探测按钮旁边）：一键卸掉 Ollama 当前已加载的全部模型（`/api/ps` 为准），结果回显在模型提示行 |

接口：`POST /api/ollama_unload`，body 可带 `{"model": "名字"}` 只卸指定模型，不带则卸全部。

代价：连续批量写词每条都要重新加载模型，单条会慢几秒；换来的是显存必空，渲染通道不会被保温模型挤爆。

已知联动：点「探测」会向每个本地模型发一条测试消息，会把模型拉进显存约 5 分钟——探测后如需显存，直接按「卸载本地模型」。


### ComfyUI text_encoders 渠道（int8 safetensors 写词）

模型选择区新增 `comfyui:` 前缀渠道：直接调用本机 ComfyUI（`http://127.0.0.1:8188`）挂载 `ComfyUI/models/text_encoders` 里的 safetensors 文本编码器（如 `qwen3.5 4B int8无审查.safetensors`），通过核心节点链 **CLIPLoader → TextGenerateV2 → SaveText** 完成写词。列表来自 `/object_info/CLIPLoader` 的 `clip_name`，ComfyUI 离线时该分组为空。

| 特性 | 行为 |
|---|---|
| 排队 | 写词以 ComfyUI 队列任务提交，与渲染任务同队列串行 |
| 显存 | 写词完成后队列空闲即 `POST /free` 卸载模型（队列忙则跳过，避免打断渲染） |
| 取结果 | 优先取 SaveText 的 history 输出，落盘 txt 仅兜底（`output/dress-gacha/dsg_*.txt`） |
| 解码 | `sampling_mode: off`（贪心，输出稳定）、`thinking` 由「思考强度」开关控制 |
| system | 设计系统提示词经 `PrimitiveStringMultiline` 接入 `system_prompt`（`use_default_template` 必须为 True 才生效） |

实测耗时（8G 显存 --lowvram，队列空闲）：4B int8 约 40 秒；9B int8 约 4.6 分钟；32B H3 nvfp4 超过 2 分钟需手动取消；`qwen_3_8b_fp8mixed` 约 3 分钟。**推荐 4B int8**。
